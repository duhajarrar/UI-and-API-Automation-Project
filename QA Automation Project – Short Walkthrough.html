Part 2: API automation

Traccar

A GPS tracking platform with a REST API

A geofence is an area on the map, sent as text:

CIRCLEPOLYGONLINESTRING

CIRCLE (31.959 35.1823, 500)

POST /api/geofencescreated, read back ✓
PUT /api/geofences/{id}updated, read back ✓
DELETE /api/geofences/{id}deleted, read back ✓

Part 2: How it’s built

Python, pytest, and requests

Part 2 - API automation testing/
├ api/traccar_api.pyone client, every call
├ data/geofence_data.pytest cases as rows
├ data/geofence_schema.pyresponse shape
├ tests/create, update, delete
├ conftest.pyfixtures
└ .envcredentials, not committed
One client classTraccarApi has login, create, get, update, and delete, like a page object for the API.
Data-drivenEach case is one row, run with pytest’s parametrize.
FixturesLog in once. Each test gets a fresh geofence, deleted after.
Valid, invalid, and edge cases, 5 response codes: 200204400401404

Part 3, step 1: The question

Can the site handle 1,000 users in 15 seconds?

JMeter on BlazeDemo, a site made for load-testing practice

Run from the command line. Every request must return 200.

Part 3, step 2: What happened

Errors0
Median response: before, during, after 371→593→486ms
Slow requests41

Slower under load, still under a second, and back to normal after. Each new HTTPS connection added 139 ms.

41 of the 1,000 requests waited 7 to 10 seconds on the server. Their connection was normal.

✓Median within Google’s 0.8 s target
✕Slowest 1% at 9 s, near the 10 s limit

Part 3, step 3: Why were 41 requests slow?

Idea 1: too many users at once? Step test: 10, 50, 100, 250, 500, 1,000 users. 0 errors, and throughput kept up.
